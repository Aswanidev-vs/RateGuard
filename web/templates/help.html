Control plane

01 / Limiting

Token buckets in practice

What the numbers mean

Limit rpm is the sustained rate. The bucket refills at limit_rpm / 60 tokens each second. Burst is the bucket capacity: the number of requests that can pass back-to-back after an idle period.

Every admitted request consumes one token. When no token is available, RateGuard answers 429 Too Many Requests with Retry-After, X-RateLimit-Limit, X-RateLimit-Remaining, and X-RateLimit-Reset.

Key handling

Tenant keys start with ag_live_ and are shown once at creation. RateGuard stores only a SHA-256 hash and a short lookup prefix, so a lost key cannot be recovered — issue a new tenant or rotate it.

Send the key as Authorization: Bearer <key> (or X-API-Key). The dashboard signs in with the separate admin key; tenant keys cannot unlock the console.

02 / Smoke test

Prove it from a shell

KEY=ag_live_your_key_here
for i in $(seq 1 120); do
  curl -s -o /dev/null -w "%{http_code}\n" \
    -H "Authorization: Bearer $KEY" \
    http://localhost/proxy/quote
done
# Expect the first `burst` requests to pass, then 429s.

One request returns a random quote from the demo upstream. The flood above should produce a run of 200s followed by 429s; Retry-After tells the client when to come back.

03 / Sandbox

Use the quote sandbox

Flood sequence

  1. Create a tenant with a small burst (for example 10) on the Tenants page.
  2. Copy the one-time key into the sandbox panel on the overview page.
  3. Press Send 1 request and note X-RateLimit-Remaining.
  4. Press Flood 200 requests. The blocked counter climbs and Retry-After appears.
  5. Watch usage counters settle after the next flush interval.

Reading cost anomalies

An hourly worker compares the AWS account's EstimatedCharges metric against a seven-day rolling baseline. A finding is recorded when spend exceeds baseline + 2σ or 1.5 × baseline, deduplicated per UTC hour, and published to SNS.

Billing data is account-wide, so findings are attached to the reserved __account__ scope rather than an individual tenant. Inject a synthetic spike during a demo by setting COST_FAKE_CURRENT and COST_FAKE_HISTORY on the Lambda.

04 / Operations

Health and limits

Endpoints

ANY /proxy/* is the rate-limited passthrough. POST /api/v1/tenants issues keys; GET /api/v1/tenants/{id}/usage returns allowed, blocked, avg_latency_ms, and p95_ms. /healthz is liveness, /readyz checks the store.

Response headers on /proxy/*
HeaderMeaning
X-RateLimit-LimitBucket capacity for this tenant
X-RateLimit-RemainingWhole tokens left after this request
X-RateLimit-ResetEpoch seconds until the bucket is full
Retry-AfterSeconds until one token is available (429 only)

Known v1 boundaries

Token buckets live in process memory and reset on restart. Usage is flushed in batches; a hard kill may lose the final batch. Latency percentiles are approximated from fixed histogram buckets. These trade-offs keep the deployment inside the free tier.
