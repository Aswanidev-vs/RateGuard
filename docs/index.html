The limiter is a bucket, not a counter

Each tenant holds a bucket. Capacity is the burst allowance; refill is limit_rpm / 60 tokens per second. A request spends one token. When the bucket is empty the request never reaches your upstream — RateGuard answers 429 with Retry-After and returns the allowance on every response.

Spend anomalies, checked hourly

An hourly Lambda pulls the AWS EstimatedCharges metric and compares it with the mean of the previous seven daily totals. The alarm threshold is the lower of mean + 2σ and 1.5 × mean, floored at 1.25 × mean so a few cents of noise on a small bill stays quiet.

A breach becomes a DynamoDB record, publishes to SNS, and appears in the operator dashboard. Billing is account-wide, so findings attach to the reserved __account__ scope rather than one tenant.

Three things to run it

  1. 1

    Point it at an upstream

    Set PROXY_UPSTREAM_URL and an admin key, then start the Go binary. It listens on port 8080.

  2. 2

    Issue a tenant key

    POST /api/v1/tenants returns an ag_live_… key once. Only its SHA-256 hash and lookup prefix are stored.

  3. 3

    Route traffic through the proxy

    Send /proxy/* with Authorization: Bearer <key>. Read the allowance off X-RateLimit-*.

export RG_ADMIN_KEY=your_admin_key
KEY=$(curl -s -X POST http://localhost:8080/api/v1/tenants \

  -H "Content-Type: application/json" \
  -d '{"name":"acme","email":"ops@acme.example","limit_rpm":60,"burst":10}' \
  | jq -r .api_key)

curl -i -H "Authorization: Bearer $KEY" \
