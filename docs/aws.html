Deploy RateGuard to AWS

Terraform runs in Docker; you run every command. This provisions EC2, DynamoDB, ECR, SSM, SNS, a cost-anomaly Lambda, and the GitHub OIDC deploy role in ap-south-1.

Learning project, not production ready. Use a disposable account, keep SSH disabled, and tear everything down when finished.

1

Prerequisites and credentials

You need an AWS account with VPC/EC2/IAM/DynamoDB/S3/ECR/SSM/SNS/CloudWatch/Lambda rights, AWS CLI v2, Docker Desktop, and Go 1.27+.

Verify identity
aws sts get-caller-identity
aws sso login --profile <your-profile>   # if you use SSO

Terraform runs in a container and must see your AWS credentials. Mount ~/.aws and pass the profile:

Git Bash — Terraform wrapper
docker run --rm \
  -v "$HOME/.aws:/root/.aws:ro" \
  -v "/$PWD:/workspace" -w /workspace \
  -e AWS_PROFILE \
  hashicorp/terraform:1.9.8 <terraform command>

PowerShell uses -v "${HOME}\.aws:/root/.aws:ro" and backticks for line continuation. Static keys can be passed with -e AWS_ACCESS_KEY_ID -e AWS_SECRET_ACCESS_KEY instead of mounting.

2

Create the GitHub OIDC provider once

Actions assumes an AWS role without a stored key. Create the provider in IAM → Identity providers if it does not already exist.

Git Bash
THUMBPRINT=$(openssl s_client -servername token.actions.githubusercontent.com \
  -connect token.actions.githubusercontent.com:443 -showcerts </dev/null 2>/dev/null \
  | openssl x509 -fingerprint -sha1 -noout \
  | cut -d= -f2 | tr -d ':' | tr 'A-Z' 'a-z')

aws iam create-open-id-connect-provider \
  --url https://token.actions.githubusercontent.com \
  --client-id-list sts.amazonaws.com \
  --thumbprint-list "$THUMBPRINT"
3

Build the Lambda binary

Terraform needs a real build/bootstrap file at plan time. Build it for linux/arm64 from the repository root.

Git Bash
mkdir -p build
GOOS=linux GOARCH=arm64 CGO_ENABLED=0 \
  go build -trimpath -o build/bootstrap ./cmd/lambda
4

Bootstrap remote state

From terraform/bootstrap/, create the S3 state bucket and DynamoDB lock table, then write terraform/backend.hcl using the outputs.

terraform/bootstrap — wrapper from step 1
<TF> init
<TF> apply -var='bucket_name=rateguard-tfstate' -var='region=ap-south-1'
<TF> output -raw state_bucket
<TF> output -raw lock_table
terraform/backend.hcl
bucket         = "PASTE_STATE_BUCKET_OUTPUT"
key            = "rateguard/dev/terraform.tfstate"
region         = "ap-south-1"
encrypt        = true
dynamodb_table = "PASTE_LOCK_TABLE_OUTPUT"
5

Set secrets and variables

Copy terraform.tfvars.example to terraform.tfvars, set an email for SNS, and leave domain_name and allowed_ssh_cidr empty for the first run. Supply secrets as environment variables.

Git Bash
cp terraform.tfvars.example terraform/terraform.tfvars
export TF_VAR_admin_api_key="$(openssl rand -base64 48)"
export TF_VAR_session_secret="$(openssl rand -base64 48)"

Save the admin key — it is the dashboard password. It is also stored in SSM and in Terraform state; keep both private.

6

Plan and apply

Run from terraform/. For a first deploy, create ECR first, push an image, then apply the rest.

terraform/
<TF> init -backend-config=backend.hcl
<TF> fmt -check
<TF> validate
<TF> apply -target=aws_ecr_repository.app
# push the first image (step 7)
<TF> plan -out=tfplan
<TF> apply tfplan
7

Push the first image to ECR

Repository root
ECR=$(cd terraform && <TF> output -raw ecr_repository_url)
aws ecr get-login-password --region ap-south-1 \
  | docker login --username AWS --password-stdin "$ECR"
docker build -t rateguard:bootstrap .
docker tag rateguard:bootstrap "$ECR:latest"
docker push "$ECR:latest"
8

Verify and smoke test

Host shell
cd terraform
<TF> output
IP=$(<TF> output -raw ec2_public_ip)
curl -s http://$IP/healthz
curl -s http://$IP/readyz
aws ssm get-parameter --name /rateguard/admin-api-key \
  --with-decryption --query Parameter.Value --output text

Open the dashboard_url output, sign in with that key, create a tenant, then send 120 requests to /proxy/quote. Expect 200s up to the burst, then 429 with Retry-After.

9

Test the cost anomaly worker

Inject fake spend, invoke the hourly Lambda, confirm the anomaly and SNS email, then re-apply to restore real settings.

Host shell
aws lambda update-function-configuration \
  --function-name rateguard-dev-cost-anomaly \
  --environment 'Variables={AWS_REGION=ap-south-1,COST_BILLING_REGION=us-east-1,COST_FAKE_CURRENT=9.5,COST_FAKE_HISTORY=1.1,1.2,1.0,1.3,1.1,1.2,1.0,DYNAMODB_TENANTS_TABLE=api_guard_tenants,DYNAMODB_USAGE_TABLE=api_guard_usage,DYNAMODB_ANOMALIES_TABLE=api_guard_cost_anomalies,SNS_TOPIC_ARN=<topic-arn>,COST_METRIC_NAME=EstimatedCharges}'
aws lambda invoke --function-name rateguard-dev-cost-anomaly /tmp/rateguard-lambda.json
cat /tmp/rateguard-lambda.json
10

Wire GitHub Actions and tear down

Set repository variables AWS_ROLE_ARN, ECR_REPOSITORY_URL, EC2_INSTANCE_ID, and PUBLIC_HEALTH_URL from Terraform outputs. Then push to main.

Teardown
cd terraform && <TF> destroy
cd bootstrap && <TF> destroy
